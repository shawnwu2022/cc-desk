# Stable opening order and repeated close

Session order and activity serve different purposes. Rows sort by `lastOpenedAt` descending, with stable session IDs resolving ties. Accepted new sessions, reopening closed history and archive restore update this timestamp. Switching an already open terminal changes selection only; output, observer notices, process status and completion never change opening order or select a background terminal. Existing project pin/name ordering and archive groups remain unchanged. There is no new session-pin system.

The timestamp uses the existing incremental `projects.json` writer and its cross-process lock. Opening-only updates preserve the current same-identity title and activity fields, while rename updates preserve the saved opening time. Exact runtime/CLI/project/source identities prevent another session from inheriting metadata. Old history without an opening time has a fixed zero fallback; imported live tabs use immutable creation time. A newly discovered exact history identity receives the original accepted opening time once. Failed display-metadata writes do not reject an admitted runtime or trigger activity-driven write replay; a fixed safe notification explains that ordering could not be saved.

The ordinary 0.18.1 close dispatch entered `close-running` confirmation after the first trailing × click. Released 0.18.3 removed that additional confirmation, and the actual App/Native terminal composition passes a single-click close with synthetic authenticated receipts. This comparison does not establish which version produced an unavailable user screenshot.

A separate repeated-click defect was reproduced against the released 0.18.3 facade: queuing a second close while the first stop was pending invalidated the first operation's selection publication. The terminal closed but the remaining terminal was not selected. Repeated closes now join only the same still-owned attempt. A replacement generation gets its own operation. A failed stop remains failed; duplicate clicks do not automatically retry it. The original five-second unconfirmed-stop rejection remains unchanged, and late output/exit/launch receipts cannot recreate a closed terminal.

Regression coverage includes real App × dispatch, Native terminal cancellation/stop/recovery and Legacy xterm stop through their adapters/facade. IPC and terminal libraries are synthetic; this is component/host evidence, not real Claude/Codex, installed Windows, taskbar or live updater acceptance. Sorting tests exercise parallel background changes, switching without movement, reopen/restore/new ordering, refresh/restart fallback, persisted metadata and two-writer name preservation. Existing exact screenshot baselines remain required.
