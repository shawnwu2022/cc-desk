# CLI program discovery

The old Claude startup used a saved program path or searched for `claude`. Native dual-CLI safe profiles deliberately leave executable trust unset, but the initial UI failed to connect the existing discovery helper. This made installed programs require manual path entry.

For a never-admitted new session with `PROGRAM_TRUST_REQUIRED`, the workspace now asks the backend to find the selected CLI automatically. The inline surface lists candidates and, for a Windows npm batch shim, its cmd runner. The user confirms **Use and start session** once. The selected executable/launcher is saved to that configuration and reused on later creation. Manual configuration remains available when discovery finds nothing or a custom launch is needed. Merely viewing discovery never saves or starts anything.

The strict request contains a profile ID, exact profile revision and registered project ID. The authenticated main window is required. Exclusion roots come from all verified registered project identities and Desk metadata; relative PATH entries and project-contained candidates are excluded. Only the fixed Claude/Codex executable names are searched. Discovery returns at most 32 candidates, no environment/argv, and never executes a candidate, invokes a shell, changes PATH/policy, or chooses a replacement for an explicit unavailable selection. Independent profiles do not read legacy configuration.

Windows native executables and cmd/bat shims are supported. A shim includes an absolute external `cmd.exe` runner from its effective ComSpec. PowerShell scripts are not silently used. Windows canonical verbatim paths cannot be passed directly to cmd for batch execution; a conventional DOS/UNC spelling is returned only after canonicalization proves identical file identity. Existing launch validation still applies, including its shell metacharacter restrictions.

Discovery and confirmation are owned by the current session selection, navigation and request intent. Editing cancels the pending automatic continuation. The profile write uses the workspace CAS revision; the acknowledged profile must match the selected path/launcher and remain the current revision. Lost acknowledgements recover by read only, with no write replay or automatic launch. The dedicated continuation retains that exact revision through preparation and final adapter admission; newer selection, navigation, configuration or project removal cancels it. The ordinary editor's separate Save and Retry behavior is unchanged.

Validation includes both-CLI filesystem fixtures, strict request/response validation, project/runner exclusions, explicit unavailable selection, UI discovery and reuse, pending-write navigation/selection/edit cancellation, reordered profile receipts, uncertain writes, and delayed preparation cancellation/revision binding. A real Windows ConPTY test discovers a temporary cmd shim and verifies synthetic argv/cwd/TTY round-trip. This proves the OS shim path, not installed Claude/Codex login/version behavior or physical application acceptance. The installed application and real user data are untouched by these tests.
