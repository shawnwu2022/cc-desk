# 移动端配对流程

## 用户操作

1. 桌面端填写自建 WSS 中转地址，进行 TLS、协议和本机身份准入校验。任一检查不通过，不生成二维码。修改地址立即废弃未完成的邀请。
2. 桌面端选择有效期 1／5／10 分钟，默认 5 分钟。展示二维码、配对码、倒计时、刷新及取消；刷新立即废弃旧邀请。相机扫码是主路径，手动配对码是兜底。两个入口对应同一份邀请和同一套准入规则。
3. App 内扫描/输入后自动配置连接所需信息；显示目标主机、站点、拟请求权限和有效期。失败保留可理解的状态，不展示完整令牌或密钥。
4. 桌面端显示待配对手机及权限，明确同意或拒绝。默认仅观察。邀请兑换必须绑定新设备的公钥、当前主机、已验证的中转和本次会话范围；只有已同意并完成双方验证后才可进入会话。
5. 已配对设备有状态和撤销入口。拒绝、取消、刷新、过期、重复兑换均不能创建连接。关闭确认不是同意。

## 二维码与配对码

二维码携带经验证的连接地址、主机身份校验信息、一次性邀请和有效期。不可携带私钥、密码、长期中转密钥或已有会话权限；邀请不能成为独立登录凭据。中转地址保持用户可配置，不内置运营域名。手输码不另外开设低强度授权路径；在实现可限速、可撤销、原子单次兑换且不泄漏令牌的同一邀请通道前，不把短码标成可用。

参考 [Codex 移动连接](https://learn.chatgpt.com/docs/mobile) 的桌面发起和手机确认，[ZCode 远程控制](https://zcode.z.ai/cn/docs/remote-control) 的扫码、复制、刷新和停止。参考的是操作流程，沿用 CC Desk 的自建中转、设备身份和桌面授权边界。

## 交付验证

- 桌面未验证或修改地址，不能生成或沿用二维码；测试默认期限、手动期限、取消及刷新。
- App 测试正常扫码、手输、错误地址、错误主机、过期、重复兑换、不同设备兑换与拒绝。只有收到有效桌面批准才能连接；默认不可输入。
- Android 正式包需发布签名，实际安装并通过手机与真实中转的配对、连接、观察和撤销。网页或模拟测试不代替真机。
- 当前移动网页视觉更新独立于上述跨端协议；不修改 RC3，也不将启动壳作为 Android 产物。

## 多桌面

设备列表以桌面公钥标识与已验证中转绑定，不用昵称或地址代替身份。每台桌面独立配对、独立批准、独立撤销。默认进入最近使用的在线桌面；可切换为按桌面筛选，或在一个列表中合并显示所有允许观察的会话。每条显式呈现来源桌面；同名会话不能串台。设备离线单独标记，不阻塞其他桌面。合并列表不扩大任何设备或会话的权限。

验收至少覆盖两台桌面同时配对、同名会话、切换返回、单机离线、单机撤销后另一台仍可观察。
