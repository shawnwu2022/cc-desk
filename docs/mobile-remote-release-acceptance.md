# 正式移动远程交付

以已发布 RC3 为对照，不改该标签。当前交付仅为测试版：完整开发后集中做静态审查与真实安全测试，再一起发布桌面包和签名原生 APK。不进稳定更新通道，不改现有生产中转。

## 完整远程控制测试版

- 电脑在「远程连接」里选择手机与当前运行的会话，明确区分「只读」和「允许控制」。只读不能输入。允许控制也不授予其他会话、远程启动程序或操作系统控制权限。
- 手机上选择已共享的会话，可以持续看输出，能输入和粘贴，并使用基本的会话按键。停用、切换电脑、会话退出或撤销后，旧画面和旧输入不能误连到新会话；不自动重发结果不确定的输入。
- 复用现有控制通道和会话写入仲裁。静态审查核对桌面授权、签名角色与会话绑定、手机输入、写入确认和停止端到端对应。观察通道及旧浏览器授权不能被升级。
- 安全测试必须真实运行。可以用隔离进程、合成数据、模拟设备和候选构建，不必用正式包；授权、输入归属、撤销、写入仲裁不能用假结果代替。至少验证已授权写入、未授权拒绝、只读拒绝、错会话拒绝、撤销和切换后旧连接失效。
- 真机或独立环境不可用时，不把非安全实机流程卡成测试版门槛；在发布说明中写明未实测范围。实际编译、签名、必需 CI 和仓库既有门禁照常，桌面和 APK 必须对应同一已审查提交，不先发空壳。

## 开发顺序

- 并发完成 Relay、桌面端、原生 Android。跨端接通前只做必要编译检查。
- Relay 使用现有自建部署和自定义 WSS 地址。邀请与长期设备授权分开：待配对请求不能访问会话；每次会话连接仍要证明持有自己的密钥；桌面撤销只影响对应配对。重启或策略续租不能把有效配对误当作过期邀请，也不能恢复已撤销的授权。
- 桌面使用独立「远程连接」入口，中转设置、配对、审批和设备管理不放入终端。验证中转后才显示二维码及配对码，默认 5 分钟，可选 1 或 10 分钟。对精确匹配的真实设备请求批准或拒绝；过期、取消、刷新会使旧邀请失效。
- Android 使用原生扫码和安全存储，使用真实传输，分别支持经批准的只读观察和会话控制。每台桌面有独立凭据。设备可快速切换；“全部”显示会话来源，按设备加会话身份做区分，单台离线不影响另一台。

## 新手上手验收

- 已有人部署中转时，新用户不用开终端、装 VPN、注册第三方账号或抄私钥。电脑版进入「远程连接」，填管理员提供的完整 `wss://` 地址并点「连接中转」。首次连接按提示点「设置这台电脑」，在本机确认后，把应用提供的公开登记信息发给中转管理员。管理员只需授权电脑一次。授权后再点「连接中转」；验证通过后才可添加手机。手机扫码或输入配对码，电脑点「同意」。
- 「已配对」和「正在共享」是两件事。没有共享时显示「这台电脑还没有共享会话」；电脑掉线时显示「电脑离线」，提示保持电脑唤醒、联网并打开 CC Desk。换网络后恢复的是连接，不恢复已经取消的共享权限，不要求重新配对。
- 自建者使用同一套部署说明：启动单个中转服务，接入现有 HTTPS 入口，再用桌面「检查连接」验收。不要求部署数据库或让每部手机重复填配置。首次授权、签名策略与到期续签仍是发布检查项；未跑通前，不宣传为全自动或一键部署。

交互参考 [Paseo 的设备配对](https://paseo.sh/docs/connectivity) 和 [Codex 的独立远程入口](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex)。沿用本项目自己的中转、配对批准和会话共享边界。

## 实机与生产补验（不阻塞测试版）

1. 在同一组待交付构建上安装原生 APK 和桌面包。手机经隔离中转完成两台桌面配对：一台扫码、一台输入配对码，均由桌面实际批准。未批准阶段不能读会话；批准前切换桌面导航和本地终端再返回，设备配对请求不因终端挂载变化而被误取消或改绑。
2. 两台桌面准备同名会话。检查全部列表来源标识、单台筛选、切换回原设备；断开一台并恢复，另一台继续可用。重启后，无需重复配对。
3. 集中验证过期/取消邀请不可用、已兑邀请不能重用，单台撤销后旧连接不能再读取，另一台仍可用，权限保持只读。
4. 只有另行安排正式生产部署时，才在实机联测通过后部署 Relay；随后验证生产链路并保留回滚步骤。测试版不修改生产。不要把私有域名、真实凭据或日用数据写入仓库。
5. 校验桌面包与 Android APK 的实际下载字节和签名。仅编译通过、Web ZIP 或启动壳都不能代替可安装的测试版。

- 共享返回未知结果时，桌面只读取一次当前中转状态，不自动重发共享请求。读取失败时继续隐藏可能过期的操作入口，等待用户主动刷新。
