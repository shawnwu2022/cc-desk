# 历史版本：目录与安装包准备

设置 → 更新 → 官方历史版本可读取官方 `shawnwu2022/cc-desk` 发行目录，显示当前平台的可用性，并明确选择一个版本。每页至多 25 条，最多读取 10 页；达到上限会显示列表可能不完整。筛选只作用于已加载的版本。草稿、测试产物和候选包不进入官方历史目录。

选择后可执行“下载并验证安装包”。Rust 持有官方发行版、安装包与签名的元数据，前端不提供下载 URL、安装路径或文件内容。后端重新检查元数据，只接受受限的官方 GitHub 资产跳转，并在私有目录验证发布者 Minisign 签名、SHA256 与大小。发布者验证成功不等于安装包身份或安装准入已通过。此阶段的历史版本安装按钮始终禁用，普通更新/发布策略保持禁用。

准备预约先返回不透明事务 ID，以便在下载期间取消。重复点击不会发起第二个准备。导航、失活或重新挂载会使旧选择失效，并通过原文档取消已知准备。取消未确认时，不显示成功或准备另一个安装包；文档已撤销时提示重新打开 CC Desk。网络、存储、签名和元数据错误只显示本地化安全提示；后台原始诊断、路径和凭据不进入界面。

## 数据与返回边界

这些历史版本没有已审核的共享数据兼容性规则，因此“保留当前数据”不可用。将来的切换流程必须使用全新 Desk 设置，并保存当前完整本地安装及匹配的 Desk 数据环境作为返回点。当前的安装包准备步骤尚未创建返回点、快照或版本切换事务。

Claude/Codex 历史、凭据、配置和项目文件仍然共享，且不会回滚。旧应用功能可能修改共享 CLI 设置，全新 Desk 设置不是旧二进制的沙箱。后续管理器、安装范围检查、真实进程退出、完整返回点和恢复流程完成前，不开放安装。

## 命令与验证

普通窗口注册五个命令：`list_history`、`select_history`、`begin_prepare_history`、`prepare_history`、`cancel_prepare_history`。请求使用原 NativeRuntime 文档桥；先验证文档，再解码至多 1 KiB 的严格 raw JSON，并在阻塞 IO 后重新检查同一个 binding、WebView 与文档凭证。准备服务保留原调用者及私有目录祖先句柄，不向另一个文档转移 token。

Windows 准备存储在后端解析的 LocalAppData 下创建具有当前用户保护 ACL 的私有目录，从已固定的目录句柄派生能力。存储/平台条件不支持时关闭准备；该能力不构成安装范围或管理器准入证明。

前端覆盖真实 UpdateSection → store → API → 文档桥组合、Rust 准备 DTO fixture、不可用列表、分页、取消/迟到响应、重挂载和文档失效。独立视觉场景使用合成内存传输并禁止真实宿主/网络调用；它生成供人工检查的未批准截图，不修改现有截图基线。Rust/Windows 实际目录能力、编译与命令边界测试仍需 Windows CI；DOM 测试不代表像素或真实安装验收。
