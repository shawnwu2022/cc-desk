# Frozen launch recipe implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Separate selected program, proven interpreter/file entry, hook delivery and structured action arguments without changing existing launch behavior.

**Architecture:** Build a backend-only immutable recipe from the existing frozen snapshot and CLI action mapper. Only the already admitted npm Cmd transport supplies a proven file-entry layout; opaque/raw routes keep their exact existing invocation. Render external argv separately from the npm preload's planned entry argv so hooks and resume cannot become interpreter options in the proven model.

**Tech Stack:** Rust, existing Windows npm Cmd/Node transport, existing fixture-only Rust tests.

**Spec:** Parent-authorized minimal stage; detailed research artifact `E:\Codex\2026-10-29\task\C3-TYPED-LAUNCH-RECIPE-READONLY.md`.

## Global Constraints

- No CLI version gate, new probe, real CLI, package download, persistent profile/request setting or permission change.
- Preserve all existing routes, selected program/runner/cwd/env and exact request/profile revision/run/generation binding.
- No migration of unproven native/wrapper routes or Unix holder changes; preserve C3 failed candidate.
- Prepared transport/layout is not actual hook capability or authenticated loaded identity.
- Local commit only after verification and independent review; no push/release/install.

## Review Focus

- Npm interpreter file entry must precede hooks/action; wrapper still selects Node.

- Request action, revision/run/generation changes cannot reuse a frozen recipe.
- Raw/opaque argv, terminators, conflicting config and user argument order remain unchanged.
- Preserved routes must not gain an inferred interpreter or a false identity/capability claim.
