## What D20 now enforces

D20 has a fail-closed real-CLI certification harness for Claude Code and Codex CLI.

The harness requires:

- an explicitly authorized test account before probing CLI/account state;
- an absolute isolated test root;
- CLI binary and both lane drivers contained by the test root, including realpath/symlink containment;
- four cells per product: CC Desk observer off/on and system-terminal observer off/on;
- isolated HOME/config/project/report roots for every cell;
- explicit test-account environment only; production OpenAI/Anthropic/Claude credentials are not inherited by default;
- a nonce-bearing fixture and a versioned prompt transform;
- raw `UserPromptSubmit` evidence collected from the real CLI hook;
- exact target identity: target/OS/architecture/CLI version plus CLI binary SHA-256;
- lane-specific host-payload provenance:
  - CC Desk: native input frame identity;
  - system terminal: explicit terminal-driver write identity;
- exact fixture hash, raw hook envelope and session/turn/cwd binding;
- observer on/off comparison for both lanes;
- unavailable or unverifiable combinations recorded as `BLOCKED`, never promoted to PASS.

The top-level `real-cli-certify.mjs` orchestrator runs Claude and Codex independently and produces one aggregate PASS/BLOCKED/FAIL decision without echoing test-account secrets.

## Binary identity correction

A RED regression exposed a fail-open condition in the matrix runner: four internally consistent evidence records could claim the same forged CLI binary hash and still pass comparison.

The corrected runner now:

1. resolves and reads the actual isolated CLI binary;
2. computes SHA-256 from that file;
3. validates the evidence structure first;
4. for structurally valid PASS evidence, compares the recorded CLI binary hash against the actual binary hash;
5. returns `REAL_CLI_BINARY_HASH_MISMATCH` on disagreement.

Validation ordering is intentional. Malformed evidence still fails with its structural reason (for example `TARGET_IDENTITY_REQUIRED`) rather than being masked by a secondary hash mismatch.

## What this does NOT certify

CI/unit tests certify the evidence format, runner isolation, fail-closed decisions, provenance checks and anti-forgery behavior. They do not constitute a real Claude Code or Codex CLI PASS.

D20 product certification remains BLOCKED until an authorized target environment executes the four-cell matrix against the actual installed/selected Claude Code binary and actual installed/selected Codex CLI binary, using real test-account authentication and real `UserPromptSubmit` hooks.

A missing account, unsupported installed hook schema, unavailable binary, missing lane driver, unverifiable host identity or incomplete evidence must remain BLOCKED. Screen scraping, model echo/repetition, writer-success receipts, synthetic hooks and fixture drivers cannot substitute for Layer-C real CLI evidence.
