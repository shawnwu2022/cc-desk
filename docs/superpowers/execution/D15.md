## Implemented production behavior

- Process lifecycle and output lifecycle are independent. Root process exit transitions
  output to draining; it is not treated as parsed/drained completion.
- Output completion requires the exact stream epoch plus a final sent offset and
  cumulative renderer parser acknowledgement through that final offset.
- `NativeRunSupervisor` owns the production PTY waiter and output reader after the
  launch reservation publishes a `NativeRun`. Process wait/reap, PTY EOF, parser
  drain and registry resource retirement are separate transitions.
- The waiter is installed before fallible transport attachment. A post-spawn reader,
  route or transport handoff failure requests stop and converges to
  Exited/Incomplete without starting another child.
- `cli_stop` is authenticated against the exact caller/run/generation. Run identity
  remains checkable after process-handle retirement so the owning document can abort
  a still-draining output stream.
- Application shutdown closes future handoffs first, revokes output routes, requests
  stop for supervised runs and waits for bounded waiter settlement. Shutdown never
  treats an accepted terminate request as proof of reap.
- Output-route revocation wakes blocked transport credit waiters, releases transport
  payload ownership and marks the stream Degraded. It does not restart the CLI.
- Degraded and Incomplete are monotone terminal output reasons: the first terminal
  failure reason is retained rather than being rewritten by later shutdown/revocation
  ordering.
- Incomplete may be recorded before a stream epoch exists, covering failures between
  process creation and transport installation.
- The TypeScript lifecycle mirror enforces the same exact run/generation/epoch,
  final-offset and monotone terminal-state rules. It is infrastructure for later UI
  adoption, not a claim that the legacy UI has already migrated.

## Targeted lifecycle evidence

Production and integration tests cover:

- process exit before PTY EOF and before the final xterm parser callback;
- exact final-offset drain and stale epoch rejection;
- route loss becoming Degraded without restart;
- descendant/tail output after root exit without assuming descendant liveness;
- explicit stop becoming Incomplete and reaping without replay;
- app shutdown while running and while already exited/draining;
- shutdown racing handoff/adoption;
- post-spawn transport attach failure terminating/reaping without replay;
- route loss followed by shutdown retaining Degraded;
- backend and frontend terminal failure precedence remaining order-stable.

The post-spawn attach test accepts zero or one probe report: zero is valid when the
child is terminated before its test handshake. The invariant is no replay/second
child plus final Exited/Incomplete ownership convergence.

## Failure and correction history

- D15 transport lifecycle changes initially broke the isolated D14 core harness
  because its test `OutputRoute` seam lacked production's new `on_revoke`
  contract. The seam was updated to mirror revocation; production transport was
  not widened or bypassed.
- Several intermediate heads failed only `rustfmt --check`; exact rustfmt output
  was applied without semantic changes.
- A new frontend order-stability test correctly exposed that TypeScript still let
  Incomplete overwrite Degraded. The implementation, not the assertion, was fixed.
- The initial attach-failure test required exactly one probe report. Windows
  demonstrated a valid faster termination before the probe handshake (zero reports);
  the test was corrected to the actual invariant: no second child/replay and
  Exited/Incomplete convergence.
- One earlier macOS D13 core run observed a loopback `ConnectionReset` while the
  same head passed D13 on Windows/Ubuntu. No D13 source correction was made for that
  isolated observation; the exact final code head passed D13 on all three OSes.

## Limits and deferred work

- A successful terminate signal is not treated as process completion; the waiter is
  still the reap authority. Shutdown has a bounded five-second settlement wait and
  logs if the host cannot converge within that bound.
- Host-wide inability to create the supervisor waiter thread is not deterministically
  fault-injected in CI. The handoff fails closed and requests stop, but this result
  is not a certification of behavior under global thread/resource exhaustion.
- Transport payload budgets bound wire payload ownership, not total application RSS,
  xterm parser memory or scrollback amplification. Broader pressure/fairness remains
  later work.
- Process wait OS failure is not fabricated into Exited/Drained. Such an uncertain
  ownership failure remains incomplete/failed rather than a false successful reap.
- Backend lifecycle state and TypeScript lifecycle primitives exist, but full native
  dual-CLI terminal UI migration remains D22-D24.
- Existing npm audit output remains 11 advisories (4 moderate, 6 high, 1 critical).
  D15 does not change package or lock files and this verification is not a clean
  dependency/security audit.
- No real model-backed Claude/Codex workflow, final packaged installer matrix,
  independent security review, merge, tag or release is claimed.
