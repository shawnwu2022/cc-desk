# D10 platform launch execution

Plan: approved v3 W2/D10 (PR07), continuing D09 #17 at df9d6e75a4f7f5a2ea1580256af1087a88305a93.

## Scope and rulings

- Work on a dedicated stacked branch, not main. No merge, release, version/dependency/lockfile change, or native user configuration mutation.
- The exact W2/D10 card was read from the mounted v3 ZIP after two Files searches returned no indexed D10 content. No invented file citation or replacement public plan was used.
- Container Git access failed at DNS resolution and no Rust toolchain is installed. GitHub Actions executes the actual Rust checks and OS process probes; no user-machine certification is implied.
- Ruling: resolve_process consumes one CliInvocation, not a second independently supplied snapshot. Invocation already borrows and checks the authoritative snapshot. ProcessLaunchSpec owns a complete environment map, not a competing set/remove overlay. No CliKind appears in the resulting generic spec.
- Ruling: preserve all existing platform behavior by moving the original platform.rs blob unchanged into platform/legacy.rs and re-exporting it. The new generic module does not call global PATH refresh or implicit CLI discovery. Existing application startup/PTY remains on the old route until the launch coordinator/lifetime integration; this is a tracked integration gap, not completed migration.
- Ruling: new explicit shell/shim profiles use a deterministic noninteractive invocation wrapper. Do not silently reinterpret legacy startup/PATH preferences as the new mode. Native interactive shells remain directly selectable.
- Ruling: cmd only accepts an explicitly tested conservative subset; expansion/control syntax must return ARG_NOT_REPRESENTABLE without running or altering it. No automatic switch to another executable/interpreter.
- Ruling: PowerShell native forwarding uses Standard argument passing and requires PowerShell >=7.3 in the wrapper. An older selected runner must exit 125 with a fixed error before starting the selected agent. Do not fall back or inject an execution-policy bypass. Runtime exit is distinct from an early resolver error.
- Ruling: Windows Bash must prevent implicit MSYS path-argument conversion in the wrapper, while argv and the top-level inherited environment remain snapshot-owned. Changes made by user-authored shell startup files/scripts remain shell behavior, not a new Desk profile authority.
- Ruling: selected paths and cwd are rechecked immediately before command construction. This is not executable-byte pinning or an atomic guarantee against on-disk replacement; lifetime/file-identity hardening remains separately reviewable.

## Test scope

New tests exercise production resolve_process -> ProcessLaunchSpec.command -> spawn_process, with D03's existing probe.mjs as the real argv/TTY/cwd/environment receiver. Native, Bash, PowerShell and conservative cmd paths have separate assertions. The environment-removal parent launches an isolated Rust subprocess to establish a real inherited sentinel without mutating global test environment. Its ignored worker is invoked explicitly, not silently skipped.

Existing bundled-runtime verification remains required before Windows PTY use. A reused runtime fixture adds duplicate existing test cases, not additional unique native features. Unix-specific cases are not accepted on the Windows job. Actual agents, UI IPC, keyboard/editor/approval behavior and installers are outside these process probes.
