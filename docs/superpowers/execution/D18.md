## Implemented contract

### Clipboard policy

- Clipboard observation distinguishes unavailable, empty text, text, image-only,
  and mixed text+image states. Empty text is never guessed to mean image input.
- Bracketed paste normalizes only CRLF/CR to LF and wraps the resulting payload in
  xterm bracketed-paste markers. It does not compact or otherwise rewrite content.
- Plain/non-bracketed single-line text remains byte-faithful at the string level.
- Plain multiline text, ESC-bearing text, and embedded bracketed-paste terminators
  require explicit confirmation before any PTY write.
- Mixed text+image clipboard content requires an explicit choice before the text
  path is used.
- Image-only clipboard data does not synthesize the old hardcoded CLI image
  shortcut. The DOM paste remains uncaptured so D18 does not invent a protocol it
  cannot prove.
- Confirmation rejection, missing decision callbacks, decision callback failure,
  unavailable clipboard and empty clipboard all produce zero PTY writes.
- A paste target is captured by tab + PTY identity before any async confirmation.
  If the PTY changes while confirmation is pending, the old paste is discarded
  instead of being retargeted to the replacement PTY.

### Keyboard ownership

- Ctrl/Cmd+V and Shift+Insert have one paste owner: xterm key emission is declined
  and the browser paste event remains available to the capture-phase arbitration
  handler.
- Shift+Enter is no longer globally rewritten into an invented terminal sequence;
  it passes through to xterm / the active CLI.
- Ctrl/Cmd+C is intercepted only when the terminal currently owns a selection.
  Without a selection the event passes through, preserving CLI control-key
  semantics.

### IME policy

- The existing xterm IME supplement is reduced to one explicit policy predicate.
- Supplement occurs only for composed `insertText` after keydown, when no real
  composition path was observed and xterm has not already emitted data.
- If xterm already emitted data, D18 never supplements it again.
- Composition-driven IMEs remain on xterm's native composition path.

## Covered D18 cases

The pure input-policy suite covers 16 cases:

1. bracketed paste line-ending normalization and wrapping;
2. plain single-line byte-faithful payload;
3. plain multiline confirmation;
4. ESC / embedded paste-end confirmation;
5. unavailable clipboard is not image;
6. empty clipboard is not image;
7. mixed text+image requires explicit choice;
8. image-only classification has no hardcoded shortcut;
9. Ctrl/Cmd+V + Shift+Insert single paste owner and Shift+Enter pass-through;
10. copy interception only with owned selection;
11. IME supplement only on the precise xterm drop branch;
12. already-emitted data is never duplicated;
13. missing clipboard data -> unavailable;
14. text-only clipboard -> not image;
15. image MIME -> image-only;
16. text + image file -> explicit mixed state.

The DOM paste tests additionally cover zero-write empty paste, image-only uncaptured
behavior, mixed-choice rejection, risky-paste reject/confirm behavior and stale PTY
rejection after async confirmation.

## Limits and next task

- D18 does not claim end-to-end native CLI input-path adoption. D16/D17 provide the
  queue/staged-writer primitives; D19 must connect and certify the terminal-host
  protocol path without source guessing.
- Image-only paste is deliberately not converted into a hardcoded Claude/Codex
  shortcut. A later integration must use a proven CLI/system capability rather
  than infer one from clipboard emptiness.
- These A-layer policy and DOM arbitration tests do not promote real CLI, WebView,
  installer or target-matrix certification cases on their own.
- No dependency/version change, merge, tag or release is part of D18.
