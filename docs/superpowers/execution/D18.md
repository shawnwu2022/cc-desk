## Implemented contract

### Clipboard evidence

- Clipboard classification is evidence-based: text, image, empty and unavailable are distinct states.
- Empty text is never guessed to mean image.
- A failed text read is never guessed to mean image.
- Image routing requires positive image evidence: an image MIME type on the DOM paste path or a successful native image probe.
- Text wins over simultaneous image evidence.
- Native clipboard probing reads text first; only a successful image read authorizes the image-key path.
- Async paste retains the captured PTY identity; if the PTY changes before the clipboard decision completes, the stale paste is discarded.
- Text paste preserves content except CRLF/CR -> LF normalization and optional bracketed-paste wrapping.
- Empty text produces no empty bracketed-paste frame.

### Paste shortcut ownership

- Only the canonical platform Ctrl+V or Cmd+V chord is intercepted.
- Alt-modified paste chords and Ctrl+Meta combinations are not silently reinterpreted.
- DOM paste is captured once at the terminal container and stops xterm's duplicate paste listener from sending the same payload twice.
- Positive image evidence may route the CLI image-paste key bytes; the key path is not selected from empty/error state alone.

### IME provenance

- The IME supplement mirrors only the known xterm 5.5 composed `insertText` drop branch.
- Fallback is emitted at most once per keydown cycle.
- A real composition lifecycle suppresses fallback.
- Any xterm `onData` emission suppresses fallback to prevent duplication.
- The fallback is sent as explicit user input instead of being injected back through xterm and reappearing as ambiguous `onData`.
