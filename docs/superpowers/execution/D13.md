## Production paths

- `ObserverRegistry`: per-run/generation random capability, exact authentication,
  duplicate-header rejection, 1,024 remembered event IDs without eviction/replay,
  4,096 binding budget, exact-lease cleanup and revocation checks before parsing
  and before delivery. External authorization/destructors run outside its lock.
- `observer_http::router`: actual loopback HTTP; authenticate before accepting the
  body, 64 KiB payload limit, eight concurrently reading handlers, three-second
  body deadline, reject Origin, fixed errors. Old `/hook` rejects requests.
- `ObserverHost`: verifies bounded application-owned plugin assets. A missing or
  modified asset, unavailable port or observer admission failure is optional: the
  native invocation remains usable, not a reason to stop or repeat a launch.
- `LaunchService`: only the reservation-winning spawn prepares the observer.
  Its frozen actual snapshot retains the environment/plugin arguments; the owned
  run holds the lease. Replay does not mint another capability. Document revocation
  and exited run state fail authorization independently of process ownership.
- Existing legacy Claude PTYs also hold authenticated leases tied to the exact
  main document. Cleanup releases the lease. Events target that owner's WebView,
  not a global bus. SessionStart only invalidates the legacy derived cache; event
  paths never extend filesystem authority. Native events use a separate topic.
- New profiles default off; raw never adds a plugin or observer values; Codex and
  Shell never use Claude observers. Only Desk's capability namespace is stripped
  from ambient/profile inputs; provider credentials and other user variables stay.
- `report-hook.sh`: no unauthenticated fallback; bounded stdin, random event ID,
  escaped curl config in stdin instead of argv or process-substitution paths, secret variables explicitly unexported, no
  curl config/proxy/redirect delegation or retry. curl deadline is three seconds;
  the registered CLI hook timeout of five seconds is the outer command deadline.
- Hook payloads carry only allowlisted bounded identity/type metadata. Prompt,
  assistant text, tool/error contents, environment values and tokens are omitted.
- `integrations/registry`, `claudeObserver`, `stores/hook`: exact-run/CLI/enable
  subscriptions, bounded replay state, disable/detach cleanup, no late callback
  activation, isolated consumer exceptions and safe listener disposal. Parallel
  hook process arrival does not establish a source sequence; activity is unknown.
  The real legacy status monitor preserves process state and no longer retitles
  from prompt text or asserts working from such events. Codex/off skips the Claude
  waiter. Local Escape invalidates an activity hint, not proof that a CLI stopped.

## Decisions and limits

- The approved D13 task is continued inline. No new architecture cycle, D14 output
  supervisor or product transport was added. Necessary pure-module extraction
  enables actual-source cross-platform tests, not a substitute implementation.
- Unknown activity is intentional for unordered hook occurrences. The cost is less
  precise GUI status, not lost CLI functionality. Identity observations are not
  authentication/config-root authority, permission grants or CLI submit receipts.
- Structured argv with an explicit `--` separator suppresses optional injection;
  no attempt is made to reinterpret arbitrary user arguments. Raw remains exact.
- Replay storage fails closed at its explicit budget instead of evicting records
  and silently accepting replay. Observation can become unavailable in long runs;
  native execution is unchanged. No heartbeat or perfect live-status guarantee.
- Disabling/detaching an observer never restarts the process. Profile edits affect
  future snapshots, not the existing run's frozen configuration. Full new-workspace
  UI controls remain D22-D24; the backend runtime gate remains closed until D14/D15.
- Already-dispatched IPC cannot be recalled. Authorization checks bound effects but
  do not claim elimination of every race after the final check. Capabilities are
  not protection against arbitrary same-user OS processes that can read memory or
  environments. Payload budgets are not an application RSS/connection-count bound.
- The reporter depends on bash, curl, od, tr and the CLI's outer timeout.
  Missing dependencies silently disable only this optional observer. No native
  auth/config/histories are mutated and no real model-backed workflow is certified.
- Author self-review only; independent review and previously reported dependency
  advisories remain outstanding. No version/lockfile dependency upgrade, main
  merge, release, tag, installation or D14 completion is claimed.

## Windows reporter correction

Observer core #1 on Windows compiled and ran 30 tests: 29 passed and the actual
Bash/curl delivery test failed. Linux/macOS passed. A synthetic diagnostic found
Git Bash curl could not open `/proc/.../fd/63` (exit 26), and checkout used CRLF.
The reporter now reads at most 65,537 bytes, rejects oversize/NUL, streams escaped
curl config on stdin, uses data-raw to forbid leading-@ file interpretation, and
pins its checkout to LF. Additional tests cover byte preservation, config-option
injection, credentials outside argv/env, byte bounds and checkout attributes.
No assertion or actual Windows delivery case was skipped.
