## Checkpoint boundary

This first increment establishes source-aware cache partitions and removes stale config-panel publication. It is **not completion of D12**: the authenticated `native_get_scope` / `native_list_resources` commands, owner/profile/run revision checks and all resource readers still need migration before the new dual-CLI UI may use them. A cache partition is not a filesystem permission or a SourceScope capability.

The D11 production `NATIVE_RUNTIME_NOT_READY` gate stays unchanged. Do not interpret passing cache tests as real CLI, live WebView, all-platform or packaged-installation certification. No native history/config deletion, version/lockfile update, main merge or release belongs to this increment.

## Reader inventory and migration boundary

| Existing entry point | Current dependency | D12 required boundary |
|---|---|---|
| `get_home_data[_indexed]`, `get_projects`, `get_project_startup_state` | Legacy default Claude root; scans also populate project mapping | Workspace registration remains the new home authority. Scoped scans enrich only; scanning errors must not remove registrations. |
| `get_sessions[_indexed]`, `get_all_recent_sessions[_indexed]`, `get_session_count` | Default-root mapping, project directories, session-name resolver | Resolve registered project reference inside an authorized SourceScope; mapping/cache partitions must include source root and identity epoch. |
| `get_session_details`, `search_session_messages` | Legacy project directories and session IDs | Read only authorized scoped directories. A session ID alone never locates data across roots. |
| `get_project_config` / basic, MCP, skills, agents, hooks helpers | Home/project settings and legacy implicit native roots | Replace implicit root and arbitrary project-path scans in the new route. Keep legacy entry points legacy-only until migrated. |
| `get_all_plugins` | `run_claude_command("plugins list --json")`, native install/marketplace paths | Cannot be reused by Codex or a new scoped route. Resolve the exact profile invocation/root and bound its output/read paths; no default-program or default-root fallback. |
| `get_all_agents`, `get_all_skills` | Plugin reader above plus user/project directories | Carry the same root/project/run scope through every nested reader; no Claude helper for Codex. |
| `get_all_mcp_servers`, config-source collection, ancestor `.mcp.json` walk | Plugin data, user/project/local files and environment expansion | Bound all source paths to the authorized project/source policy; never expose credentials or silently expand the scan after errors. |
| `find_valid_plugin_path`, marketplace resolution and plugin subresource readers | Installation paths with implicit home fallback | Remove default-root fallback from the new chain; validate each selected resource reference. |
| Legacy `delete_sessions` | Mutates native Claude history | No generalized native-delete command in the new projection API. Workspace hiding is independent. |
| `project_service::list_projects` | Desk workspace registrations plus optional legacy metadata enrichment | Preserve its independence from native sessions and projection availability. |

Do not move every legacy reader at once or turn `store.rs` into a rewrite. Each new resource route must pass backend ownership and real two-root tests before exposure; an unsupported resource returns unavailable rather than invoking a legacy default reader.

## Tests and evidence

- Local baseline: `npm run test:ci`, 54 files / 655 tests passed.
- Config race RED: five tests failed on the baseline (late success, late failure, late finally, clear, cached reselection). Two additional tests failed for stale visible data while switching and empty selection. The eight-test suite passes after request-ownership guards and no raw error logging.
- Windows CI #194 (`35851393954`, test head `3cb810f`) actually reproduced root replacement: expected `RIGHTname`, returned `LEFT-name`. The mapping worker initially failed because its fixture cwd did not exist; that fixture failure is **not** isolation RED. Test-only head `2807602` corrects the cwd with a real temporary directory and JSON-escaped Windows paths.
- Backend RED is tracked against the test-only commits in PR #20. The first scaffold mistakenly called `flush` rather than the existing `flush_pending`; that compile failure is **not** behavioral RED. It was corrected without changing production behavior.
- Root replacement fixture creates two distinct directories before renaming, uses identical session IDs, file lengths and exact modification times, then reads through the production indexed reader. It requires a rebuild and the second root's title.
- Legacy-mapping test runs the actual home reader in a separate bounded child test process. Its ignored worker is invoked and checked by the normal parent test; it is not manual coverage.

The schema-v2 cache key contains CLI, verified source-root identity, canonical decimal identity epoch and project-directory identity. Legacy projection readers use the Claude partition at epoch zero. `SourcePartition` does not expose files or acquire run authorization. Mapping partitions retain path spelling because their values contain those paths; they are capped at 64 and invalidated together. Profiling helpers use the same scoped mapping entry point, not a hidden global cache.

Final GREEN counts and exact commit/run IDs belong in the PR verification record, not inferred from an earlier head.

## Remaining D12 work

1. Bind SourceScope registration and each resource read to D11's real document admission; revalidate owner, profile revision / run access and identity epoch at effect time and before returning delayed results.
2. Determine root from backend-authorized profile/run evidence. Raw/shell/unknown argument semantics must remain unknown; configured environment is not automatically proof of a running CLI's effective identity.
3. Hold and validate root handles, confine filesystem reads, and reject root replacement/symlink escapes without falling back. Cache identity is not a race-free filesystem sandbox.
4. Migrate history/search plus MCP/skills/agents/plugins through scoped production readers. Add Codex-specific projections only for supported native sources; do not parse Codex history with the Claude parser.
5. Implement requestEpoch/SourceRef validation in the authenticated frontend projection wrapper, preserve project registration when enrichment fails, and prevent new panels from calling legacy native-delete/default-root operations.
6. Re-run the full regression set, owner/revision revocation and delayed-reply tests before marking D12 complete. D13 begins after that gate.
