# Ordinary desktop updater

The 0.18.2 patch keeps the existing fixed official GitHub endpoint and Minisign public key. Optional `updaterProxy` applies to both manifest/package requests and provenance requests. Empty settings preserve process/system proxy inheritance; CLI profile or legacy launch environment settings are never copied into the updater.

The Rust host checks the public non-draft, non-prerelease release, exact version/tag/source, the release body's existing validation policy and source line, tag resolution, and the source configuration's version and trust key. The selected package and `.sig` must be unique uploaded official assets with bounded sizes and SHA-256 digests. The manifest signature must match the uploaded signature asset. Candidate/test-only/non-publication markers still exclude a package. This uses the existing official repository/TLS and published signature trust; it does not introduce another signing key or promotion service.

The host retains the actual Tauri `Update` and returns only a one-shot admission receipt. Renderer updater-plugin installation permissions are absent. Confirmation refuses running, starting and unknown session ownership; the existing shared admission gate freezes new starts and mutations atomically. Before effectful installation, the host rechecks the frozen release proof, verifies downloaded asset size/hash and Minisign signature, and checks quiescence again. Known preparation failures release the review freeze. Once the installer is entered, unknown results retain the freeze and cannot replay the installer. Ordinary Tauri install/restart remains the platform implementation.

Public errors contain only an allowlisted code and stage. Both persistent logs and debug output redact raw upstream updater details, including attacker-controlled malformed manifest strings. The backend emits fixed `update_diag` codes. Clipboard detection reads only DOM text and item MIME metadata; positive image evidence routes the existing CLI image-paste shortcut, with no image reads, temporary files or clipboard capability expansion.

The local `tests/updater-core` adapter runs the same policy and HTTP tests registered in the complete Windows Rust inventory. It proves actual loopback explicit/inherited proxy routing, bounded HTTP failures, source exclusions, official asset binding and a real public Minisign vector. Component tests cover confirmation, busy/unknown session refusal, no duplicate/unknown install replay, proxy hydration/navigation, stale checks and secret-free errors. They do not execute a native installer, establish real Claude/Codex image-paste acceptance, or certify Windows rendering. Those platform observations remain separate evidence.

0.18.2 is an unpublished candidate until the existing formal release workflow completes. Published 0.18.1 assets and the fixed historical acceptance inputs are untouched.
