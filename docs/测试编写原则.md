## CC Desk 测试编写原则

通用 Agent 规范和测试命令索引统一维护在 [AGENTS.md](../AGENTS.md)，各工具入口只引用标准文件，加载与维护方法见 [agent-guides.md](agent-guides.md)。本文维护测试细节；CI 的来源、分片与计数契约见 [ci-performance.md](ci-performance.md)。

### 1. 测行为，不测实现

只验证"输入什么、输出什么"，不验证内部怎么做到。测试与实现解耦，重构不改测试。

### 2. 一个测试只验证一件事

一个用例只断言一个行为点。失败时看名字就知道哪里坏了，不需要读测试代码排查。

### 3. 只测自己的代码

不测第三方库、框架、CLI 工具的能力。边界停在 `invoke()` 调用和文件 I/O 处，不 mock 整条链路。

### 4. 不为测试而造抽象

不引入 test helper 类、factory 函数、共享 fixture 文件。测试数据直接写在用例里，读一个用例就是完整上下文。

### 5. 失败信息必须自解释

断言时写清楚 `expected X, got Y` 的语义，不只是 `assert(eq, a, b)`。报错时不用猜。

### 6. 不测显而易见的正确性

getter/setter、纯赋值、类型定义、简单 props 传递——这些不写测试。测试的价值在于捕获"看起来对但实际错"的逻辑。

### 7. 优先覆盖错误路径和边界条件

快乐路径 AI 一般能写对，真正的 bug 藏在空值、越界、并发、格式异常里。正常流程写一个就够了，异常流程多写几个。

### 8. 测试即文档

用例名要描述具体行为，英文函数名遵循第 12 节的格式，中文注释说明场景。新读者看测试列表就能理解模块行为。

### 9. 能跑才算数

单元测试必须本地一条命令跑通，不依赖外部服务、网络或隐含环境变量。真实进程、PTY、CLI 与平台专项明确记录前置条件和实际执行结果；未具备目标环境时保留未验证状态，不通过 mock、删断言或排除用例制造通过。

### 10. 增量添加，不追求覆盖率

新功能或修 bug 时补测试，不为已有代码批量补写。覆盖率是副产品，不是目标。

---

### 11. 测试文件独立存放

所有测试放置在单独的 `tests/` 文件夹中，不与源码文件混放，不写在源码同一文件中。
- 前端：项目根目录 `tests/` 目录
- 后端：`src-tauri/src/tests/` 目录

### 12. 用例命名规则

- 用例函数名用英文，不超过 40 字符，特性范围内唯一
- 采用动宾结构，用 `_` 分割意图、预制条件、观察点，如 `DeepMerge_NestedObjects_PreservesBothLevels`
- 编号格式：`Feature_SubFeature_SeqNum`（如 `DeepMerge_Recursive_001`），序列号 3 位起
- 每个测试函数上方用一句中文注释描述测试目标
- 避免使用受 UI 布局约束的描述，以及特殊字符

### 13. 用例内容编写规则

- **用例间独立**：用例之间不依赖执行顺序或其他用例的副作用
- **避免冗余**：不重复设计已覆盖的场景
- **用词精准**：禁用"很多、一些、部分、大量、多次、随机、任意、一段时间、大概、正常、异常、边界值、非法值"等模糊词，必须实例化（如不说"非法值"，说"输入特殊字符@#¥"）
- **保留字统一**：用"检查"代替"观察/查询/确认"，用"设置"代替"赋值/给予"，用"执行"代替"运行/操作"
- **前置条件**：说明被测对象状态、预置数据、环境要求，不用"已正常安装"等抽象描述
- **测试步骤**：操作对象和方法实例化表达，参数设具体值，不遗漏动作
- **预期结果**：针对检查点的明确描述，必须可确认

---

**总结一句话**：测试是给未来的 AI 和自己写的保险单——每个用例都能独立跑、独立读、独立定位问题。

---

### 14. 运行分层：快速环与全量证据分离

测试执行分两层，写代码时用快速环，提交前与 CI 走全量证据：

**前端（Vitest，耗时随宿主、负载和源码变化）**

- `npm run test:fast`：普通 DOM 与纯 Node 测试；迭代时仍优先用 `npm test -- <文件或目录>`，或 `npm run test:watch` 挂 watch。
- `npm run test:process`：真实子进程、脚本及本地 HTTP 契约；保留真实执行，不为提速改成 mock。
- `npm run test:stress`：5,000 条会话、30 个 owner、120 次状态/选择/布局变化，保留完整工作量和断言。
- `npm test`、`npm run test:all`、`npm run test:ci`：完整 Vitest 库存，包含以上各组。`test:all` 仅指 Vitest；CI 的独立 Node policy、Rust、视觉与实际平台验证继续由各自入口执行。
- `vitest.config.ts` 复用 Vite 插件、别名和构建身份。纯 Node/进程清单显式分类，DOM 组自动接收其余普通测试；视觉 fixture 继续使用独立配置。分组保持文件隔离，`window.crypto` setup 仅在 DOM/stress 组执行。
- `tests/config/testProjects.test.ts` 用一次真实 Vitest 文件发现核对入口选择、完整库存和重复项，避免反复加载配置增加自身开销；新增测试必须保持完整入口可发现，需要浏览器全局的文件不能放入 Node 组。

**Rust（`npm run test:rust:lib` 等价 `cargo test --locked --lib`，仍包含 library 中的真实进程集成测试）**

- Cargo 命令从 `src-tauri` 执行；Windows 先在仓库根执行 `node scripts/prepare-conpty.mjs`。读取 [Rust 目录指南](../src-tauri/AGENTS.md)；修改 Native CLI backend 还需读 [CLI 目录指南](../src-tauri/src/cli/AGENTS.md)。
- 日常迭代：按域过滤，如 `cargo test --locked --lib launch`、`cargo test --locked --lib D11_Registry`；写代码时先跑红绿的过滤子集
- 全量 `cargo test` 含大量真实进程集成测试（owned_pty、run_supervisor、version_history、*_live 等），本地可达 30 分钟级——完整证据以 CI 的 windows-rust-shard-runner 分片执行为准，本地不要把全量当日常环
- 此前本机全量样本记录了 19 个前置条件相关失败；这是历史观测，不是允许忽略的固定失败名单：
  - `version_history::windows::manager_process` 域 18 个：要求宿主进程不被 Windows Job 对象包含；agent/IDE 是否 job-contained 必须实际查询，CI 由 windows-ordinary-preflight 预检该条件
  - `tests::native_cli_platform::D10_Bash_ShellAndShimRoundTrip_07` 1 个：要求本机安装 Git Bash（缺失时报 "Git Bash is a required test dependency"）
- 每次失败仍须核对实际阶段、错误和宿主条件；新失败不能自动归类为上述环境问题或非回归。失败于 fixture 初始化的时间不能作为单用例校准数据，不增 skip/exclusion，不放宽 NTFS/ACL/Job 门禁。
- 持有 Windows 目录句柄的 fixture 必须先释放句柄、最后释放 `TempDir`；结构体字段按声明顺序释放，不能把 `TempDir` 放在这些句柄前面。`HistoryContext_FixtureCleanup_041` 用实际文件树核对释放后无残留；不要添加 `Drop` 实现阻止原有字段移动，也不要削弱生产 `FILE_SHARE_DELETE` 保护。诊断失败留下的本任务 fixture 先保存并核对字节，再仅清理精确拥有的临时根，不用于生产未知进程或恢复数据。
- 保持严格 `cargo clippy --locked --all-targets -- -D warnings`。要求的英文测试名称可在单个 `#[cfg(test)]` 模块添加 `#[allow(non_snake_case)]`，不要为了 lint 改名破坏原始库存，也不要全局放宽警告；生产 helper 放在测试模块之前。
- 耗时校准保留原始失败和 deadline；300 秒本机探针超时不证明用例挂死。恢复用例在原 20 分钟 harness 上限内完成约 379 秒；单次 `opt-level=1` 试验约 354 秒且增加编译成本，未采用。完整结果与来源见 [CI 性能记录](ci-performance.md)，不能据此缩减 fixture、改变断言或直接写入分片权重。
- 提交前至少跑一遍受影响域的过滤子集 + `npm run typecheck`

**慢的根因与边界**：真实进程、真实 PTY、真实 CLI 证据链是本项目的测试价值所在（见 native-cli-v3 文档），效率优化以「分层让日常环变短」为目标，不通过砍真实进程测试实现。

- 可选加速：安装 sccache 后仅在本地设置 `RUSTC_WRAPPER=sccache`，缓存重复编译；未安装不影响流程，缓存命中也不等于实际构建提速，需要测量。
- 纯文档或入口引用修改检查内容、相对链接与作用域即可，不为此重跑完整 Rust/真实 CLI。不要为提速取消测试发现检查、文件隔离、断言或工作量。
- 测试命令与分类变更时同步根指南、本文、README 和 CI 性能记录，不在 `CLAUDE.md`、`GEMINI.md` 或 Copilot 入口再维护一份测试规则。
- 跨平台 fixture：传给 Node 子进程的文件 URL 用 `fileURLToPath` 转为路径，Windows Rust fixture 使用 `.exe`；文本结构检查可规范 CRLF，但源码来源哈希仍按实际字节核对。Bash 契约测试用 `--noprofile --norc` 隔离个人启动脚本，并保留真实 reporter、严格 stdout/stderr、正文相等与凭证不外泄检查。
- 负向进程测试先证明同一真实入口能接受合法输入，再核对失败退出码和固定拒绝原因；`MODULE_NOT_FOUND` 或进程未启动不能算门禁拒绝成功。

### CI 构建复用与生产源码加载

- Roundtrip debug 的两个 binding 场景仍各跑一次完整 Tauri/Rust 构建，首次构建必须执行原前端与 ConPTY 准备 hook。只有该次构建成功且 `dist/index.html` 存在，第二次才可用临时配置关闭重复 hook；不读取其他 job 或旧 checkout 的 `dist`。Clippy、失败退出、binding 原始字节恢复和临时配置清理均保持。
- `historyRoundtripBuild.node.mjs` 执行 workflow 中的真实 PowerShell 编排，用隔离的构建替身分别验证成功、首次失败、前端缺失、第二次失败和 Clippy 失败。它验证编排，不能表述为真实应用编译或 CLI 往返验收。
- 独立 Node 的粘贴生成器与 trace 测试共享 `.github/scripts/transpile_production_source.cjs`，加载实际 `pasteText.ts` 和 `inputPolicy.ts`。AST 只处理生产构建常量 `import.meta.env.DEV=false`；包含相同文本的字面量和正文不能改写，未知环境开关仍须失败，已有 trace 开关的启用/禁用两分支保留。
- 只隔离宿主 API；trace fixture 的实际剪贴板读取器若意外被调用必须抛错，不能读取用户剪贴板或 mock 生产分类/粘贴实现。完整黄金样本、正文相等与原 release gate 清单必须保留。
