# 撤除独立恢复/归档面板

2026-11-12，基于 0.27.0-rc.6 集成工作树。Claude 主记录可恢复移除和 OpenCode 独立原生归档面板不再作为产品功能提供。原有会话树、Desk 归档/恢复、Codex 原生归档与永久删除的能力边界保持不变。

## 当前界面

- 普通归档抽屉不再显示“Claude 恢复区”和“OpenCode 原生归档”两个入口，也不再提供选择会话后新增移除/原生归档的操作。
- Claude 仅保留旧数据找回：抽屉打开后经现有授权来源只读检查已存在的恢复日志。没有旧记录时不显示额外内容；存在尚未找回、损坏或未知记录时内联显示。只能将旧日志的原件恢复到原位置，不能创建新移除记录、覆盖冲突文件或清空恢复目录。
- OpenCode 已原生归档的历史行保留单条“从原生归档恢复”确认。没有全局面板或选择器，写请求始终为 `archived: false`。普通 Desk 归档仍是原有显示标记，不借此新增原生归档。原生恢复不启动终端，也不替用户清除 Desk 标记。
- Claude 读取请求绑定当前抽屉/项目/来源，关闭、换项目或来源变化会废弃迟到结果；恢复写入不因关闭而重放。未知恢复在跨组件状态中保留，未完成请求不被一次列表读取解除。操作结束后只能靠只读定位重新核实，原路径冲突时保留双方。来源加载或失败时保留旧记录显示并禁用恢复；损坏记录数量按稳定来源保留，只在该来源成功读取后更新，其他空来源不能清掉提示。
- OpenCode 沿用准确来源、同步撤销确认、未知写屏障与正向状态核实。取消、同 tick 来源变化、重复点击及读取失败不能变成新的原生归档或重放恢复。即使目标行暂时消失，只要存在未决操作，抽屉仍保留仅供只读核查的提示与刷新入口；缺席不算成功。

## 数据与后端

本次不执行数据迁移、自动恢复、自动清理或永久删除。`.ccdesk-recovery-v1`、原生数据库、项目数据和 Desk 索引都保持原样。现有认证后端及其安全校验保留以兼容已存在记录；这不代表在产品界面继续开放新增移除或独立归档。

开发用 `tests/native-delete-webview/main.ts` 将旧数据准备改为明确的合成源认证调用，再用实际抽屉验证找回。它不再声称已经撤除的操作仍是产品 UI。没有对用户配置根或真实会话调用这些准备步骤。

## 回归范围

- `archiveFeatureRetirement.test.ts`：普通抽屉无额外入口，原会话空状态保持。
- `nativeSessionRecycle.test.ts`：旧原件恢复、无新移除、冲突/未知不覆盖、关闭与来源变化拒绝旧按钮、迟到读取不串项目、未知写只读核查、损坏记录提示。
- `opencodeArchive.test.ts`：仅恢复、一次发送、取消/来源变化、跨重开未知状态、读取失败/换根不伪造成功、原生恢复后 Desk 恢复仍可用。
- 继续回归原有归档、删除、会话行和工作区行为，以及类型检查和生产构建。

以上前端测试不是 Rust、真实 CLI 或安装版 WebView 验收。本次未发布、未升级安装包，也未更改版本号。
